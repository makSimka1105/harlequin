# Форк Harlequin под работу со связями и vim-навигацию

Дата: 2026-09-20
База форка: upstream `v2.15.0` (ветка `maksibon-fork`)
Целевая база для проверки: `retail_training` на localhost, адаптер postgres

## Задача

Писать джойны в harlequin, не уходя в psql и не выискивая связи глазами. Сейчас,
чтобы сравнить два связанных поля, приходится либо держать схему в голове, либо
открывать psql параллельно. Автодополнение помогает только когда путь уже известен.

Пять изменений, в порядке возрастания цены:

1. Вставка из каталога кладёт путь до поля, а не голое имя в кавычках.
2. Навигация по дереву клавишами vim, включая прыжки по таблицам и схемам.
3. Панель связей под каталогом: FK текущего узла, прямые и через цепочку.
4. Модальный редактор с минимальным набором команд vim.
5. Фильтр каталога по подстроке.

## Что уже есть в апстриме и переиспользуется

Разведано по коду 2.15.0, не по документации:

- `HarlequinConnection.search_catalog(term, kind)` — `adapter.py:116`, гейт
  `IMPLEMENTS_CATALOG_SEARCH`. Реализован в pg-адаптере 1.4.1 (`adapter.py:381`),
  один `union all` по шести уровням, `ilike`, строки приходят родитель-раньше-детей.
  В TUI не выведен: торчит только как `hsql --catalog-search`.
- `harlequin.statements.captures()` — tree-sitter по SQL. `autocomplete/symbols.py`
  уже достаёт из буфера идентификаторы и пары `context.name`.
- FK-запросы к `pg_constraint` отлажены в `harlequin_postgres/interactions.py`
  (`show_describe_table_constraints`, `show_describe_relation`).
- Полсотни действий `code_editor.*` в `actions.py`: все движения курсора,
  удаления, undo/redo, буфер обмена.
- `ContextMenu` (`components/data_catalog/__init__.py:39`) — всплывающий OptionList
  у курсора дерева.
- `bindings.py:12`, `key_needs_priority()` — фикс #1131: alt+буква приходит как
  текст и требует priority-бинда. В 2.13 этого нет, отсюда неработавшие alt+hjkl.

Плагин-точек только две — `harlequin.adapter` и `harlequin.keymap` (`plugins.py:79,85`).
UI-хуков нет, поэтому весь UI делается форком ядра.

## Раскладка репозиториев

- `~/src/harlequin`, ветка `maksibon-fork` — форк ядра. Весь UI, все действия,
  раскладка `harlequin_vimnav`, ребейз на теги апстрима.
- `~/src/harlequin-pg-fk` — отдельный маленький пакет. Подкласс
  `HarlequinPostgresConnection` с запросом внешних ключей, entry point
  `harlequin.adapter` под именем `pgfk`. Репозиторий `harlequin-postgres` не
  трогается и обновляется независимо.

Почему FK-запрос не в ядре: ключ сопоставления графа с каталогом — строка
`qualified_identifier`. Она должна строиться той же функцией кавычения, что строит
каталог, иначе рассинхрон написания — вопрос времени. Эта функция живёт в адаптере.

Ветка на фичу. Кавычки и навигация вмерджатся за вечер, фильтр дерева будет жить
дольше; одно не должно блокировать другое.

## 1. Разрешение путей и алиасов

Общий фундамент: им пользуются вставка из дерева, вставка из панели связей и
всплывашка алиасов.

Новый модуль `harlequin/references.py`. Одна функция `read_scope(text) -> BufferScope`,
один проход tree-sitter. `BufferScope` — кортеж `RelationRef(name, alias, is_cte)`
плюс поиск алиаса по элементу каталога.

Отдельно от `autocomplete/symbols.py`: тот отвечает на «какие идентификаторы есть в
буфере» для автодополнения, этот — на «под каким именем таблица доступна сейчас».

### Извлечение алиасов

Проверено на живом парсере. Пары собираются **обходом детей узла `(relation)`**, а
не парными капчурами: `captures()` возвращает независимые списки, и порядок в них
разъезжается (`person.person` встаёт напротив `c`).

```
'sales.salesorderheader'   alias=None
'recent'                   alias='r'      (CTE)
'sales.customer'           alias='c'
'person.person'            alias='p'      (написано через as)
'sales.store'              alias=None
```

### Сопоставление с каталогом

По суффиксу сегментов, после снятия кавычек и casefold. Написанное `sales.customer`
совпадает с каталожным `"retail_training"."sales"."customer"`.

Если под суффикс подходит больше одного элемента (голое `customer` при наличии
`sales.customer` и `archive.customer`) — совпадения нет, вставляется полный путь.
Угадывать нельзя: неверный алиас даёт молча неправильный запрос, полный путь в
худшем случае длиннее.

CTE попадают в scope (нужны всплывашке), но каталожным элементам не сопоставляются:
у них нет `qualified_identifier`.

### Форма вставляемого пути

- таблица в буфере под алиасом → `c.customerid`;
- во всех остальных случаях → `sales.customer.customerid`.

Оба варианта — валидный SQL. Промежуточная форма `customer.customerid` не
используется: она короче, но добавляет третью ветку и ломается на неоднозначности.

### Кавычки

Сегмент остаётся без кавычек, если подходит под `^[a-z_][a-z0-9_]*$` и не является
зарезервированным словом. Список зарезервированных берётся из
`connection.get_completions()` — адаптер отдаёт их с `type_label="kw"` и
`priority=100` (`harlequin_postgres/completions.py:27`), приложение их и так
запрашивает на `app.py:1751`. Так правило работает для любого адаптера.

`"Order Date"`, `"Select"`, `"MixedCase"` кавычки сохраняют.

### Потребители

Одна функция `path_for(item, scope)`:

- вставка из дерева — `app.py:589`, сейчас там голый `message.insert_name`;
- вставка из панели связей;
- всплывашка алиасов.

### Тесты

Чистые юнит-тесты без UI: алиас через `as` и без него, CTE, таблица без алиаса,
неоднозначный суффикс, идентификатор с пробелом, идентификатор — ключевое слово,
пустой буфер, буфер с синтаксической ошибкой посреди.

## 2. Панель связей

### Данные

В ядро — `HarlequinConnection.get_foreign_keys() -> Sequence[ForeignKeyEdge]`,
дефолт пустой кортеж. Адаптеры без поддержки ничего не показывают и не падают.

`ForeignKeyEdge` — фрозен-датакласс: `constraint_name`, `from_relation`,
`from_columns`, `to_relation`, `to_columns`. Все идентификаторы — в написании
`qualified_identifier`.

Реализация для postgres — в `harlequin-pg-fk`, запрос к `pg_constraint` по образцу
`show_describe_table_constraints`. Грузится один раз воркером при готовности
коннекта (`app.py:569`), перечитывается по `refresh_catalog`. На целевой базе это
10 рёбер за ~9 мс, поэтому граф держится в памяти целиком, без ленивой подгрузки.

### Обход графа

Рёбра проходятся **в обе стороны**: от `salesorderdetail` до `storeinventory` иначе
не добраться, они связаны общим `product`, на который оба ссылаются. Направление
шага запоминается, `→` и `←` в панели остаются честными.

BFS, до 4 шагов (значение выносится в конфиг; диаметр целевой базы — 3). Каждая цель
показывается один раз кратчайшим маршрутом, при равенстве — алфавитно первым.
Посещённые узлы повторно не разворачиваются, это же решает проблему циклов.

### Отображение

Панель слушает `Tree.NodeHighlighted`.

- курсор на таблице — все её связанные поля;
- курсор на поле — только связи этого поля;
- курсор на схеме или БД — свёрнутый счётчик, без списка;
- связей нет — приглушённая строка, панель не схлопывается, чтобы layout не прыгал.

Две секции:

```
┌ Relations · salesorderdetail ─┐
│ ПРЯМЫЕ                        │
│ → productid                   │
│     production.product        │
│       .productid              │
│ → salesorderid                │
│     sales.salesorderheader    │
│       .salesorderid           │
│                               │
│ ДАЛЬШЕ                        │
│ ▼ productcategory      3 шага │
│    1 ▶ production.product     │
│    2 ▶ production.            │
│         productsubcategory    │
│    3 ▼ production.            │
│         productcategory       │
│        productcategoryid [##] │
│        name              [s]  │
│ ▶ customer             2 шага │
└───────────────────────────────┘
```

`ПРЯМЫЕ` — один FK, сразу с парой полей. `ДАЛЬШЕ` — цель и число шагов; раскрытие
даёт маршрут пронумерованными таблицами; раскрытие любой таблицы маршрута — её поля.
Поля промежуточных таблиц доступны намеренно: они нужны, когда пишешь средний джойн
цепочки.

Секция `ДАЛЬШЕ` переключается биндом (`relations_panel.toggle_indirect`), по
умолчанию включена, состояние живёт между запусками.

Панель не генерирует `join ... on ...` и не показывает цепочки равенств.

### Вставка

Enter на узле-поле кладёт путь по правилам раздела 1. Enter на узле-таблице — путь
до таблицы по тем же правилам.

### Место и фокус

`app.py:435` — каталог и панель заворачиваются в `Vertical`: каталог `height: 1fr`,
панель фиксированной высоты, свой бинд показать/скрыть. Панель фокусируемая, в цикле
`focus_next` идёт сразу после дерева, внутри работают те же j/k.

### Тесты

Юнит-тесты обхода графа отдельно от UI: маршрут через общего родителя, цикл,
недостижимая таблица, выбор кратчайшего из двух равных. Снапшоты панели: поле с
исходящей связью, поле с входящей, `ДАЛЬШЕ` выключено.

## 3. Навигация по дереву

`j`/`k` кода не требуют: действия `data_catalog.cursor_up`/`cursor_down` уже есть,
это строчки в раскладке. То же для панели связей.

`shift+j`/`shift+k` — новые действия `data_catalog.cursor_next_container` и
`cursor_previous_container`. Скан от `cursor_line` до `last_line`,
`get_node_at_line()`, предикат, `move_cursor_to_line()`. Только публичное API
textual; в `_tree_lines` не лезем, иначе каждый апгрейд textual — лотерея.

Предикат — `node.allow_expand`. Harlequin выставляет его на `database_tree.py:447`
как `bool(item.children) or not item.loaded`: у колонки False, у таблицы и схемы
True, у плейсхолдера `loading…` False. Отсюда правило получается без отдельных
веток: с колонки прыжок на следующую таблицу, с последней таблицы схемы — на
следующую схему, потому что она и есть следующий разворачиваемый узел по порядку
строк.

Известное ограничение: таблица без единой колонки после загрузки получает
`allow_expand = False` (`database_tree.py:561`) и прыжком пропускается. Случай
вырожденный, не чиним.

### Раскладка

Пакет `src/harlequin_vimnav/` в форке, по образцу существующего
`src/harlequin_vscode/`, плюс entry point `harlequin.keymap`. Конфиг схлопывается до
`keymap_name = ["vscode", "vimnav"]`, бинды версионируются вместе с кодом и
покрываются тестами рядом с `test_keymap_vscode.py`.

Переключение панелей остаётся одиночным `alt+hjkl`. Честный вимовский аккорд
`ctrl+w h` невозможен: textual аккордов не поддерживает, запись `"ctrl+b,f9"` — это
список альтернатив, а не последовательность. `ctrl+hjkl` тоже отпадает: `ctrl+j`
исторически равен переводу строки, `ctrl+h` — забою, textual объявляет
`"ctrl+j": ["newline"]` (`keys.py:254`), и в vscode-раскладке harlequin `ctrl+j`
уже занят запуском запроса.

### Тесты

Функциональные: прыжок с колонки на следующую таблицу; с последней таблицы схемы на
следующую схему; прыжок на последней строке не уводит курсор за край; прыжок в
дереве с одной раскрытой веткой из трёх.

## 4. Модальный редактор

Немодифицированные печатные клавиши намеренно оставлены textual (`bindings.py:12`),
поэтому `h`/`j`/`k` через систему раскладок harlequin забиндить нельзя — нужен
перехват на уровне виджета.

`CodeEditor` (`components/code_editor.py:57`) получает реактивное поле `mode` со
значениями `normal` и `insert` и обработчик `on_key`. В insert обработчик не делает
ничего. В normal съедает печатные клавиши и разводит по таблице, пропуская всё
модифицированное — `ctrl+enter`, `alt+h`, функциональные продолжают работать в обоих
режимах.

### Таблица команд

Большая часть — маршрутизация в существующие действия, а не новый код:

```
h j k l   → cursor_left / down / up / right
w b       → cursor_word_right / cursor_word_left
0 $       → cursor_line_start / cursor_line_end
gg G      → cursor_doc_start / cursor_doc_end
ctrl+d/u  → cursor_page_down / cursor_page_up
x         → delete_right
dd        → delete_line
D         → delete_to_end_of_line
u         → undo
p         → paste
```

Пишется с нуля только состояние режима, разбор двухклавишных последовательностей и
входы в insert: `i` на месте, `a` на символ правее, `o` новой строкой ниже, `I` и `A`
на края строки.

Двухклавишные (`gg`, `dd`) — автомат с буфером ожидающей клавиши, сброс по `Esc` и
по любой клавише, не продолжающей последовательность. Таймаута нет, как в vim.

### Не входит в первую версию

Счётчики (`3j`, `5dd`), операторы с движениями (`dw`, `c$`), визуальный режим,
регистры, текстовые объекты. Счётчики требуют настоящего разбора фразы вместо
словаря и без операторов-с-движениями дают мало; добавляются потом правкой того же
автомата.

### Esc

Если открыт список автодополнения — `Esc` закрывает его и режим не трогает. Иначе
уводит в normal. Обратный порядок гасил бы подсказки при выходе из insert.

### Индикатор и конфиг

Режим — в подзаголовке рамки редактора: `NORMAL` / `INSERT`.

`vim_mode = true` в профиле включает слой, `start_mode` задаёт режим нового буфера,
по умолчанию `normal`.

Для тяжёлой правки остаётся `alt+e` — открыть буфер в настоящем `$EDITOR` (фича
2.14). Наш слой с ним не конкурирует.

### Тесты

Функциональные, нажатиями клавиш: `hjkl` двигают курсор и не печатают буквы; `i`
возвращает набор текста; `Esc` при открытом автодополнении не меняет режим; `dd`
удаляет строку; `gg` после одиночного `g` и после `g` с посторонней клавишей ведут
себя по-разному; `ctrl+enter` запускает запрос из обоих режимов.

## 5. Фильтр каталога

Поиск — **подстрока**, не fuzzy: `ilike '%term%'`. По `custid` ничего не найдётся,
`customerid` такой подстроки не содержит; найдётся по `custom`, `id`, `order`.

Источник — `connection.search_catalog(term, "all")`, гейт
`IMPLEMENTS_CATALOG_SEARCH`. У адаптера без поддержки `/` показывает уведомление, а
не падает. Один запрос на шесть уровней, регистронезависимый, строки приходят
родитель-раньше-детей — сборка дерева из плоского списка одним проходом.

`Input` над деревом внутри вкладки Databases, открывается по `/`, прячется по `Esc`.
Внизу панели строка счётчика совпадений.

### Два дерева, а не перестройка одного

Результат рисуется отдельным экземпляром дерева, настоящий остаётся смонтированным и
скрывается. `Esc` возвращает ровно прежнее состояние — позицию курсора и раскрытые
ветки — мгновенно и без похода в базу. Перестройка одного дерева означала бы либо
потерю этого состояния, либо код его сохранения, что дороже.

Фильтрованное дерево статическое: ленивой подгрузки нет, узлы построены сразу и
раскрыты — результат поиска мал по определению.

Ввод дебаунсится на 250 мс, запрос уходит воркером, предыдущий незавершённый
отменяется.

### Совместимость с остальными фичами

Адаптер возвращает настоящие `CatalogItem` с правильным `qualified_identifier`,
поэтому `path_for()` и FK-граф узнают узлы фильтрованного дерева наравне с
обычными. Это делает рабочим целевой сценарий: нашёл поле поиском → ушёл в панель
связей → вставил связанное поле.

### Фокус

`/` открывает ввод с фокусом. `Enter` уводит фокус в фильтрованное дерево, фильтр
остаётся. `Esc` из дерева возвращает в ввод, `Esc` из ввода сбрасывает фильтр.

### Тесты

Функциональные: подстрока, встречающаяся на двух уровнях; пустой результат; `Esc`
восстанавливает раскрытия и позицию курсора; вставка из фильтрованного дерева даёт
тот же путь, что из обычного. Юнит-тест сборки дерева из плоских результатов
отдельно от UI.

### Возможное развитие

Fuzzy-матчер уже есть — `autocomplete/completers.py:175`, `_fuzzy_match`. Натравить
его на результаты можно, но тогда запрашивать надо весь каталог и фильтровать
локально. Решение отложено: если подстроки на практике не хватит, это правка одной
функции, не архитектуры.

## Порядок реализации

1. Разрешение путей и кавычки (раздел 1).
2. Навигация по дереву и раскладка `harlequin_vimnav` (раздел 3).
3. Панель связей и пакет `harlequin-pg-fk` (раздел 2).
4. Модальный редактор (раздел 4).
5. Фильтр каталога (раздел 5).

Первые два пункта дают пользу в тот же вечер. Пятый самый дорогой и идёт последним.

Каждый пункт — своя ветка и свой план реализации. Общий у них только раздел 1,
который остальные четыре используют, поэтому он идёт первым и мерджится до начала
работы над панелью связей.

## Решённые вопросы

| Вопрос | Решение |
|---|---|
| FK в дереве или отдельной панелью | Отдельная панель под деревом |
| Алиасы: полоска, вкладка, всплывашка | Всплывашка по клавише, переиспользует `ContextMenu` |
| `shift+j` с колонки | На следующую таблицу, не на соседнюю колонку |
| Поиск: палитра или фильтр дерева | Фильтр над самим деревом |
| Что вставляет enter | Путь до поля; алиас если есть, иначе полный |
| Непрямые связи | Цель → маршрут таблицами → поля, раскрытием |
| Глубина vim | Минимальный модальный режим в редакторе сразу |
| Переключение панелей | `alt+hjkl`, не `ctrl`, не аккорды |

## Открытые вопросы

- Лимит глубины BFS — 4 шага, выносится в конфиг. Проверить на реальной базе
  масштаба AdventureWorks, не мал ли и не велик ли.
- Fuzzy вместо подстроки в фильтре — решается после недели использования.

## Проверка перед стартом

Апгрейд с 2.13 на 2.15 нужен до любой работы: он чинит alt-бинды в редакторе
(#1131, #1152) и приносит `search_catalog` в pg-адаптере. Перед тем как что-то
менять в раскладке, `alt+hjkl` проверяются на 2.15 с уже исправленным `config.toml`.
